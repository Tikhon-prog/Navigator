# PWA «Поколение» для iPhone

Отдельная веб-версия интерфейса школьного приложения. Каталог `website/` не заменяет `web/`: последний принадлежит Flutter Web.

## Уже подготовлено
- Минималистичный мобильный интерфейс под iPhone с безопасными областями экрана.
- Разделы «Главная», «Расписание», «Карта», «Допы» и «ИИ» без рекламных баннеров и декоративной псевдокарты.
- Компактная нижняя навигация, состояния экранов, переходы назад средствами Safari и короткая установка PWA.
- PWA manifest, значки, standalone-режим и Service Worker для офлайн-оболочки.
- Явные состояния-заглушки, чтобы не выдавать отсутствующие школьные данные за реальные.

## Пока не подключено
Школьная база, аккаунт/SSO, расписание, официальные планы этажей, список ДОПов, ИИ-модель и отправка push. Для этого сначала нужно выбрать и согласовать API и сервер. Не добавляй в клиент пароли или секреты.

## Локальный просмотр
Из корня репозитория:

```bash
python -m http.server 8080 --directory website
```

Открой `http://localhost:8080` на том же компьютере. Для полноценного тестирования на iPhone сайт нужно опубликовать по HTTPS: Service Worker работает только в безопасном контексте. Обычный HTTP по IP-адресу компьютера в локальной сети не равен localhost.

## Установка на iPhone
1. Открой HTTPS-адрес в Safari.
2. Нажми «Поделиться».
3. Выбери «На экран Домой».
4. Включи «Открывать как веб-приложение», если переключатель доступен.
5. Нажми «Добавить».

## Подключение API позже
Веб-клиент должен обращаться только к публичному HTTPS API. Реальные данные и авторизация не добавляются до согласования домена, схемы входа, CORS, cookies/token flow и прав доступа. Service Worker не кеширует API-ответы и авторизованные запросы.

## Ограничения iOS
Web Push доступен для веб-приложений, добавленных на экран «Домой», на iOS 16.4 и новее. Нужны разрешение пользователя, Service Worker и сервер отправки push. Safari не поддерживает невидимые push: полученное уведомление необходимо сразу показывать пользователю. PWA не может запретить iOS закрывать системное уведомление или гарантировать его повторное появление после очистки. Статус «не прочитано» нужно сохранять внутри приложения до открытия напоминания.

PWA также не может гарантировать фоновую загрузку большой ИИ-модели после сворачивания/закрытия сайта. Загрузку можно реализовать с прогрессом и возобновлением, пока страница активна; для системной фоновой загрузки на iOS нужен нативный клиент и поддерживаемые iOS фоновые задачи.

## Обновление
После изменения интерфейса увеличивай версию кеша в `service-worker.js`, чтобы установленные копии получили свежую оболочку.
