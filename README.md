# «Поколение» — школьное приложение

**Версия приложения: `0.2.1` (build `7`)** · Flutter / Dart · Android и Windows; в репозитории также есть iOS-конфигурация и CI workflows.

«Поколение» — школьное приложение с офлайн-картами этажей, поиском и категориями помещений, избранными кабинетами, построением маршрутов, расписанием, дополнительными занятиями, домашними заданиями и локальным ИИ-помощником. Серверные возможности для школьных аккаунтов подключаются отдельно.

Для iPhone подготовлена отдельная мобильная PWA-оболочка в каталоге `website/` (Safari → «Поделиться» → «На экран Домой»). Она не заменяет Flutter Web в каталоге `web/`; подключение школьных данных и API пока не настроено. Инструкция: [`website/README.md`](website/README.md).

## Быстрый старт

Для единого окружения Flutter/Dart, Python и Android SDK без установки этих инструментов на каждый ноутбук см. [разработку в Docker](docs/DOCKER_DEVELOPMENT.md). Запуск: `scripts/dev-container.ps1` в Windows PowerShell или `bash scripts/dev-container.sh` в Linux. Docker-контейнер собирает Android APK; Windows EXE по-прежнему требует нативной Windows-среды с MSVC.

Подробное и единое техническое руководство: **[docs/PROJECT_DOCUMENTATION.md](docs/PROJECT_DOCUMENTATION.md)**. В нём описаны структура исходников, локальная сборка, сервер, конфигурация, API, роли, SSO, уведомления, тесты и требования к выпуску.

Для автоматической настройки чистой Windows 10/11 x64 прочитай [инструкцию сборки](docs/BUILD_INSTRUCTIONS.md). Скрипт автоматизации остаётся в корне: [setup_and_build.ps1](setup_and_build.ps1).

Для тестовой сборки **сразу APK и Windows EXE без сервера, API-ключей, Firebase и других секретов** используй [`build_test.ps1`](build_test.ps1) из корня репозитория:

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\build_test.ps1
```

Скрипт устанавливает зависимости проекта, запускает Flutter-тесты и анализ, собирает отладочный APK и Windows EXE в автономной папке с нужными DLL и ресурсами. Результаты будут в `dist\test\android\` и `dist\test\windows\`; рядом с Windows EXE создаётся SHA-256. ZIP не создаётся. Это тестовые сборки, а не подписанный релиз. Для Android-сборки используются JDK 27 и Android SDK; Gradle 9.9.0 запускается на JDK 27, а байткод приложения намеренно остаётся Java 21 для совместимости с Android. Для Windows EXE нужны Visual Studio 2026 или Build Tools 2026 с workload **Desktop development with C++**, Windows SDK и ATL.

Сборка по умолчанию не передаёт адрес API: карта, локальные данные расписания и заметки рассчитаны на работу офлайн. Настоящие школьные аккаунты/SSO, серверные объявления и push требуют отдельно развёрнутой и настроенной инфраструктуры. **Не встраивай пароли, токены, Firebase service-account ключи или серверные секреты в Dart-код/APK/EXE** — файлы клиента можно извлечь.

## Основные возможности

- Офлайн-планы 1-го, 2-го и 3-го этажей, поиск помещений, категории (учебные, лаборатории/IT, мастерские, спорт/здоровье, администрация, общие пространства), избранные кабинеты, масштабирование и пошаговая маршрутизация.
- Локальные данные расписания и выбор расписания по классам; обратный отсчёт до конца урока/перемены.
- Раздел дополнительных занятий, маршрут до кабинета и локальные напоминания при доступном времени занятия.
- Локальный список домашних заданий, контрольных и проектов: предмет, срок, приоритет, отметка выполнения, фильтры «Сегодня»/«Просрочено» и системные напоминания по желанию.
- Локальный ИИ-помощник на Qwen: после загрузки GGUF-модели работает без облака и использует инструменты приложения, включая поиск кабинетов и построение маршрутов по школьному графу.
- Объявления с кешированием, личные заметки на устройстве и школьный аккаунт с ролевыми возможностями.
- OIDC Authorization Code + PKCE для школьного входа; серверные аккаунты, назначения сотрудников, аудит и дополнительные уведомления при настроенной инфраструктуре.

Карта, категории помещений, избранное, локальный список заданий и заметки не требуют работающего сервера. Локальная нейросеть требует однократной загрузки модели; скорость зависит от устройства. Серверный функционал и синхронизация заданий между устройствами требуют отдельной настройки и не активируются одним только фактом сборки APK.

| Путь | Назначение |
|---|---|
| `lib/main.dart` | Основной интерфейс, расписание, справочник и навигация |
| `lib/school_portal_page.dart` | Интерфейс школьного аккаунта/портала |

| `lib/student_tasks_page.dart` | Локальные задания, дедлайны и напоминания |

| `website/` | Отдельная PWA-веб-версия для iPhone; самостоятельный интерфейс HTML/CSS/JS |
| `test/`, `backend/tests/` | Тесты Flutter и сервера |
| `docs/` | Единое руководство и вспомогательные документы |

## Сервер

Сервис использует FastAPI. Публичные справочники и расписание могут загружаться из локального JSON или HTTPS API; учётные записи, сессии, назначения, индивидуальные записи ДОПов и аудит обслуживаются серверным SQLite-хранилищем. Firebase Cloud Messaging необязателен и выключен в примере конфигурации.

Не выставляй контейнер API напрямую в интернет: текущий Compose публикует порт только на `127.0.0.1:8000`; перед ним нужен правильно настроенный HTTPS reverse proxy. Все реальные секреты остаются на сервере. Не встраивай серверные пароли, token secrets или Firebase service-account credentials в APK.

## Безопасность и ограничения

- Не коммить заполненный `.env`, пароли, приватные ключи подписи или Firebase service-account JSON.
- Установи случайный `NAVIGATOR_TOKEN_SECRET` длиной не менее 32 символов и сильный пароль первичного администратора (не менее 14 символов).
- Публичные endpoint'ы должны отдавать только сведения, которые разрешено читать без входа; роли и доступ к индивидуальным данным проверяются на сервере.
- Навигационные тесты не делают план официальной эвакуационной схемой. Карты и маршруты нужно сверить с утверждёнными школьными планами.
- Push-уведомления доставляются по best-effort и не заменяют официальные экстренные каналы.

**Статус проверок:** перечень команд и тестов приведён в [техническом руководстве](docs/PROJECT_DOCUMENTATION.md). Наличие тестов в репозитории не является подтверждением, что они успешно выполнялись в конкретной сборке.
