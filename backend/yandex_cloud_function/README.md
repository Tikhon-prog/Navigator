# Navigator backend для Яндекс Облака

Backend рассчитан на HTTPS Cloud Function + динамические таблицы Яндекс Вики.

## Переменные окружения
- `WIKI_TOKEN` — OAuth-токен серверной функции, хранить только в секретах окружения Cloud Functions.
- `ORG_ID` — идентификатор организации.
- `GRID_IDS_JSON` — JSON с ID таблиц, например `{"Admins":"...","BaseSchedule":"...","Supplements":"...","Announcements":"..."}`.

Никогда не кладите OAuth-токен или секретный API-ключ в Flutter-приложение, репозиторий или публичные логи.

## Эндпоинты
- `GET /health`
- `GET /schedule?class_id=8-informatics`
- `GET /supplements`
- `GET /announcements`
- `POST /admin/login` — **намеренно отключён и возвращает HTTP 503**.

Публичные GET-эндпоинты не требуют входа: публикуйте через них только данные, которые допустимо читать любому человеку, знающему URL. Не выдавайте через них листы Admins, Devices, AuditLog или Settings.

## Перед включением административного доступа
Текущая функция входа не выдаёт сессию и не является безопасной авторизацией. Прежде чем реализовывать её заново, необходимо:
- хранить пароли с Argon2id, scrypt или bcrypt и уникальной солью;
- ограничивать частоту попыток входа;
- выдавать короткоживущие отзываемые сессии или токены;
- проверять роль и право доступа на сервере для каждого защищённого запроса;
- вести серверный аудит и не раскрывать внутренние исключения клиенту.

`X-Navigator-Key` в Flutter-клиенте не является секретом: значение, включённое в APK, можно извлечь.
