# Локальный ИИ, расписание и предпочтения навигации

## Модель и размер приложения

Основная модель — **Qwen2.5-0.5B-Instruct Q4_K_M** из репозитория bartowski на Hugging Face:

- файл: `Qwen2.5-0.5B-Instruct-Q4_K_M.gguf`;
- размер на странице модели: **398 МБ**;
- SHA-256: `6eb923e7d26e9cea28811e1a8e852009b21242fb157b26149d3b188f3a8c8653`;
- лицензия GGUF-квантизации: Apache-2.0;
- [карточка и прямой файл](https://huggingface.co/bartowski/Qwen2.5-0.5B-Instruct-GGUF/blob/main/Qwen2.5-0.5B-Instruct-Q4_K_M.gguf).

Модель не входит в Flutter assets и не должна попадать в APK/EXE. Пользователь выбирает её загрузку из экрана локального ИИ-чата. В приложении остаются интерфейс, код и native runtime для llama.cpp; поэтому размер APK не равен размеру одного Dart-кода и может быть больше 100 МБ, но отдельные 398 МБ модели в APK не упаковываются.

Скачивание выполняется в `.part` файл. До активации проверяются:
1. HTTP-ответ и полнота скачивания;
2. минимальный ожидаемый размер;
3. четыре байта заголовка `GGUF`;
4. SHA-256 для основной Qwen-модели.

При ошибке временный файл удаляется. Рабочая копия хранится в application support directory. После загрузки для диалога не требуется интернет. На слабых устройствах используются CPU-only, два потока и сокращённый контекст 1536 токенов. Скорость ответа зависит от процессора и свободной памяти.

Есть компактный SmolLM2 135M (~105 МБ), но он слабее для русского языка и предлагается как запасной вариант, а не основной школьный помощник.

## Изменение математических уроков через чат

Команды обрабатываются детерминированным парсером на стороне приложения. Модель не получает право напрямую записывать произвольный JSON в SharedPreferences.

Пример: «Во вторник геома, а в среду ВиС и алгебра».

- Если во вторник три математических слота, все три отображаются как «Геометрия».
- В среду первые два слота получают «Вероятность и статистика» и «Алгебра».
- Если в среду есть третий математический слот, чат спрашивает, что поставить третьим уроком.
- После ответа формируется предварительный вариант на проверку.
- Запись происходит только после явного «подтверждаю». «Отмена» оставляет старые настройки.

Число слотов берётся из фактических временных слотов математических предметов выбранного класса. Изменяются только персональные названия математических уроков, существующий каталог расписания класса не переписывается.

## Предпочтения навигации

Распознаются команды вроде:
- «Я не хочу идти около 202, проложи альтернативу» — сохранить предпочтение обходить кабинет 202.
- «Больше не обходи 202» — убрать это предпочтение.
- «Ты неправильно построил маршрут около 319. Перепроверь» — сохранить замечание к маршруту для проверки карты.

Предпочтения локальны и разделяются по идентификатору школьного аккаунта на общем устройстве. Маршрутизатор продолжает использовать настоящий граф коридоров. Для участков вблизи отмеченного помещения добавляется мягкий штраф; связи графа не удаляются. Если альтернативный маршрут невозможен без разрыва графа, приложение не должно выдумывать коридор.

Замечание около кабинета 319 не перемещает дверь и не переписывает геометрию автоматически. Запись сохраняется для аудита: физическую карту должен проверить человек по достоверному плану школы. Это важно, чтобы свободная текстовая команда не создала маршрут через стену или закрытую лестницу.

Последний маршрут запоминается локально, поэтому сообщение о проверке может использовать недавнюю точку назначения даже после повторного открытия чата.

## Категории помещений

В фильтре карты используются категории:
- учительские;
- администрация;
- математика;
- наука и лаборатории;
- информатика и технологии;
- гуманитарные;
- творческие;
- мастерские;
- спорт;
- медицина и поддержка;
- общие пространства;
- учебные кабинеты.

Классификация выводится из названия помещения в справочнике, а не из предположений ИИ. Если для какого-то кабинета в справочнике указано слишком общее название, его категорию можно будет уточнить в каталоге.
