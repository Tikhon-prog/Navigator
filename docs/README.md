# Документация проекта

Этот файл — карта документации репозитория **Navigator**. Он помогает найти инструкции по сборке, устройству проекта, серверной интеграции, безопасности и выпуску приложения.

> **Важно:** наличие документа с описанием функции не доказывает, что функция полностью реализована и проверена в коде. Перед релизом сверяйте документацию с исходниками, конфигурацией и результатами тестов. Документы о планах и аудитах не следует считать подтверждением готовности функций.

## Сборка и проверка

Из корня репозитория:

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
```

Команды предполагают установленный Flutter SDK и корректно настроенный Android toolchain. Если в репозитории есть специальные скрипты сборки, сначала прочитайте [BUILD_INSTRUCTIONS.md](../BUILD_INSTRUCTIONS.md) и используйте предусмотренный там сценарий. Успешная сборка сама по себе не подтверждает корректность серверных функций или поведения на устройстве.

## Настройка окружения и секреты

- Используйте [.env.example](../.env.example) как справочник имён переменных.
- Не коммитьте реальные токены, пароли, ключи подписи, приватные сертификаты или production-конфигурацию.
- Не помещайте серверные секреты в мобильное приложение: всё, что встроено в APK, потенциально можно извлечь.
- Перед запуском серверной части проверьте инструкции в [SERVER_INTEGRATION.md](SERVER_INTEGRATION.md) и правила безопасности в [SECURITY.md](SECURITY.md).
- Если переменная указана в примере, это ещё не доказывает, что код действительно использует её. Проверьте места чтения конфигурации в исходниках.

## Что считать полной документацией

Практически полная документация должна поддерживаться вместе с кодом и включать:

- актуальную архитектуру приложения и схему потоков данных;
- перечень экранов и пользовательских сценариев;
- описание каждого реализованного серверного endpoint, метода авторизации, ролей и прав доступа;
- схему базы данных и правила миграций, если используется БД;
- таблицу переменных окружения с назначением, обязательностью и безопасными примерами;
- воспроизводимые инструкции локального запуска, сборки, тестирования и релиза;
- обработку ошибок, ограничения и известные проблемы;
- автоматические тесты и подтверждённые результаты их выполнения.

## Текущий статус документации

В репозитории уже есть несколько подробных документов по сборке, серверной интеграции, безопасности, структуре исходников, исправлениям и планам. Поэтому документация **не пустая**, но по одному списку файлов нельзя честно подтвердить, что она полная, согласована с текущим кодом или что все описанные функции реализованы. Следующий правильный шаг — техническая сверка документов с исходниками и тестами, а затем обновление конкретных разделов по найденным расхождениям.
