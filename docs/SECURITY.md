# Безопасность школьного приложения «Поколение» 0.2.0

## Что защищено
- Пароли серверных аккаунтов хранятся с солью и scrypt; сравнение хешей выполняется безопасным способом.
- Короткоживущие access-токены подписываются серверным секретом; refresh-токены ротируются, а выход отзывает сессию.
- Роли и назначения учеников проверяются на сервере для защищённых операций.
- Мобильные access/refresh токены хранятся через системное защищённое хранилище; старые копии из обычных настроек удаляются после миграции.
- Публичные справочники ограничены разрешённым списком. Индивидуальные записи ДОПов, учётные записи, устройства и аудит не должны быть доступны анонимно.
- Конфигурация источника данных допускает локальный JSON и HTTPS API. Удалённые HTTP-источники запрещены; HTTP оставлен только для loopback-разработки.
- CI проверяет файлы окружения, известные шаблоны токенов и частные ключи.

## Чего эти меры не гарантируют
- Локальные проверки прав в мобильном приложении не являются границей безопасности против владельца устройства или человека, способного изменить APK.
- Адрес API и клиентский идентификатор не являются секретом.
- Публичные конечные точки без входа могут отдавать только данные, которые разрешено читать любому человеку.
- Firebase push — best effort и не заменяет школьную систему оповещения, пожарную сигнализацию, 112 или утверждённую процедуру безопасности.

## Секреты
- Реальные секреты хранятся только в настройках окружения сервера/хостинга. Не коммить заполненный \`.env\`, signing keys, пароли или Firebase service-account JSON.
- В более ранней истории репозитория ранее находился токен доступа к внешнему сервису. Если его ещё не отозвали, отзови его и выпусти новый; удаление файла не стирает значение из старых коммитов.
- После устранения старого секрета проверь историю Git и при необходимости очисти её по принятой процедуре, не переписывая историю без согласования с сопровождающими репозитория.

## Требования перед production
1. Школьный IT подтверждает OIDC issuer, client ID, redirect URI и доверенные claims.
2. Администратор задаёт сильный \`NAVIGATOR_TOKEN_SECRET\` не короче 32 символов и пароль технического администратора не короче 14 символов.
3. Внешний API публикуется только через HTTPS reverse proxy, с централизованным rate limiting и мониторингом.
4. База данных хранится на постоянном защищённом томе; резервное копирование и восстановление проверены.
5. Школа согласовала назначение ролей, обработку персональных данных, сроки хранения и правила экстренных уведомлений.
6. Маршруты сверены с утверждёнными планами. Автотест связности не подтверждает безопасность пути и не сертифицирует эвакуационную схему.
